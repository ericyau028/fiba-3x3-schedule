# FIBA 3x3 時間表網站 開發紀錄

這份文件記錄 2026 FIBA 3x3 TV Package 時間表網站的製作過程、程式架構、遇到的問題與解決方法，供日後維護或重做時參考。

## 1. 專案背景

工作來源是 `2026 FIBA 3x3 TV Package.xlsx`，內容是 22/8 至 24/8 的直播流程表。操作人員需要照著時間表錄影或直播，因此需要一個網頁：

- 一列一列顯示每個時間段要做什麼
- 過去、30 分鐘內、進行中的狀態提醒
- 開始與停止、Live 與 End Live 之間用關聯線連接
- 清楚顯示正在使用 obs-1、obs-2 或 vMix
- 表單輸入後自動產生「開始」和「結束」兩列

## 3. 製作過程

### 3.1 讀取 Excel

先用 `openpyxl` / `pandas` 讀取 xlsx，確認結構：

- 工作表只有一個「直播流程表」
- 22/8、23/8、24/8 各自有日期列和表頭列
- 表頭為：開始時間(UTC+8)、賽事、地區、操作、描述、結束時間、關聯、使用工具
- 操作包含：開始錄影、停止錄影、Live、End Live、Live 轉S2
- 關聯用字母表示，例如 `a` 開始錄影關聯到 `c` 停止錄影，`d` Live 關聯到 `i` End Live（跨日）

匯入邏輯放在 `server.py` 的 `import_xlsx()`，遇到日期列就切換目前日期，遇到「開始時間(UTC+8)」就切換為資料區。

### 3.2 後端

後端用 Python 標準庫 `http.server`，不需要安裝第三方套件：

- `GET /api/schedule`：讀取全部時間段
- `POST /api/schedule`：新增一組開始 / 結束時間段
- `PUT /api/schedule?id=...`：更新時間段
- `DELETE /api/schedule?id=...`：刪除時間段

資料存在 `data/schedule.json`。首次啟動時如果沒有資料檔，會自動從 xlsx 匯入 19 列。

### 3.3 前端

前端使用原生 HTML / CSS / JavaScript，沒有框架，避免安裝和建置成本：

- 時間表按日期分組
- 每一列顯示時間、賽事、地區、操作、描述、結束時間、關聯、使用工具
- 左側有「關聯軌道」，每條關聯線使用獨立車道，不會重疊
- 狀態顏色：過去為淺灰、30 分鐘內為黃色閃爍、進行中為綠色
- 右上角顯示目前時間和「下一步」

### 3.4 表單與自動產生

表單欄位：

- 日期（手動）
- 開始時間（手動）
- 賽事：Challenger、WT、WS、CUP
- 地區（手動）
- 操作：開始錄影、直播
- 描述（手動）
- 結束時間（手動，旁邊即時顯示例如 `5h 30m`）
- 使用工具：obs-1、obs-2、vMix
- 關聯（新增時自動產生，編輯時可自由改）

按「完成」後自動產生兩列：

- 開始錄影 → `開始錄影` + `停止錄影`
- 直播 → `Live` + `End Live`

如果結束時間小於或等於開始時間，結束列會自動排到下一日，例如 23:00 開始、01:30 結束，停止列會出現在下一日。

### 3.5 編輯功能

每列右側有「編輯」按鈕，也可以直接按關聯格（例如 `→ c`）開啟編輯。編輯時：

- 日期、開始時間、結束時間、賽事、地區、描述、工具都可改
- 結束時間只對「有結束時間的開始列」開放
- 關聯可以改或清空
- 如果關聯沒有改變，開始列和對應停止列會同步更新時間
- 如果關聯改變了，只改連線，不會自動改動其他列

### 3.6 部署成 GitHub Pages

GitHub Pages 不能執行 Python，所以前端加入「網頁版模式」：

- 優先嘗試連本機後端 `api/schedule`（相對路徑）
- 連不到就讀 `schedule-static.json`，資料存在瀏覽器 `localStorage`
- 網頁版的新增、編輯、刪除都寫入瀏覽器，只影響該瀏覽器

`export_static.py` 用來把 `data/schedule.json` 匯出成 `public/schedule-static.json`。

部署使用 GitHub Actions：

```yaml
on:
  push:
    branches: [main]
```

Actions 會把 `public/` 上傳到 GitHub Pages。

## 4. 代碼編寫方式

### 4.1 資料模型

```json
{
  "id": "seed-a",
  "letter": "a",
  "date": "2026-08-22",
  "time": "15:30",
  "datetime": "2026-08-22T15:30:00+08:00",
  "event": "Challenger",
  "region": "Beijing",
  "operation": "開始錄影",
  "description": "Session 1",
  "end_time": "18:50",
  "end_date": "2026-08-22",
  "end_datetime": "2026-08-22T18:50:00+08:00",
  "relation": "c",
  "tool": "obs-1",
  "source": "seed"
}
```

### 4.2 關聯語義

- 「開始列」的 `relation` 指向對應「結束列」的字母
- 結束列本身沒有 `relation`
- 新增時自動分配下一組字母
- 編輯開始列時：
  - 關聯沒改 → 同步更新對應結束列的時間、地區、描述、工具
  - 關聯改了 → 只更新目前這一列，不碰其他列

### 4.3 關聯線不重疊

關聯線畫在時間表左側的 SVG 軌道內：

- 每條線有自己的 `x` 車道
- `x = padX + 車道序號 * laneW + laneW / 2`
- 線是垂直直線，因此不同車道永遠不會重疊
- 車道標籤用文字加白色描邊，不佔用背景框

### 4.4 狀態計算

每個時間段的狀態：

- `past`：已經結束或時間已過
- `soon`：開始時間在未來 30 分鐘內
- `active`：現在時間落在開始與結束之間
- `future`：其他

前端每秒用伺服器時間（`offset`）更新狀態，避免依賴瀏覽器時區。

## 5. 遇到的問題與解決方法

### 5.1 日期顯示變成 21/8

**問題**：使用者看到日期從 21/8 開始，但 xlsx 是 22/8。

**原因**：`dateLabel()` 用 `new Date("2026-08-22T00:00:00+08:00")` 後再讀 `getUTCDate()`。UTC+8 的 8/22 00:00 換算成 UTC 是 8/21 16:00，所以被倒推一天。

**解決**：日期標題直接從字串拆出年月日，星期用 `Date.UTC(y, m-1, d)` 計算，完全不經過時區轉換。

### 5.2 時間表寬度不足

**問題**：桌面畫面要左右捲動。

**原因**：欄位固定寬度太多，關聯軌道也佔了 172px。

**解決**：

- 欄位改窄：`76px 70px 76px 110px minmax(100px, 1fr) 72px 54px 68px 84px`
- 軌道車道從 18px 改為 14px
- 側欄從 360px 改為 320px
- 頁面內距從 16px 改為 12px
- 1280px 寬視窗下不再橫向捲動

### 5.3 找不到編輯關聯的地方

**問題**：使用者不知道在哪裡改關聯。

**原因**：關聯欄位只在編輯模式顯示，而且編輯按鈕只是鉛筆圖示。

**解決**：

- 關聯欄位常駐顯示在表單
- 新增模式禁用並顯示「完成時自動產生」
- 編輯按鈕改成文字「編輯」
- 按時間表上的 `→ c` 關聯格也會直接開啟編輯

### 5.4 網頁版關聯編輯無效（最關鍵的 bug）

**問題**：把 row j 的關聯由 `l` 改成 `k`，按更新後又跳回 `l`。

**原因**：送出表單時，`payload` 沒有帶 `id`。網頁版走 `updateLocalItem(state.items, payload)`，程式用 `payload.id` 找要更新的列，結果找不到，直接 `return`，資料完全沒有被改。

本機後端版沒有這個問題，因為 PUT 的 id 是放在 URL 的 `?id=...`。

**解決**：在 `payload` 加入 `id: state.editingId`。修正後在全新 port 的靜態伺服器與線上 GitHub Pages 都驗證：`l → k` 能保存且重新整理後仍為 `k`。

**除錯過程**：

- 在網頁版重現問題
- 加 `console.log` 確認 `payload.relation` 是 `k`
- 發現 `UPD_ITEM` / `UPD_AFTER` 沒有出現，代表 `updateLocalItem` 提早 return
- 再用寫入 `document.body.dataset` 的方式確認，最後發現是 `payload.id` 遺失

### 5.5 GitHub Pages 不能跑 Python

**問題**：GitHub Pages 只能放靜態檔案。

**解決**：加入網頁版模式，改用 `schedule-static.json` + `localStorage`；本機 Python 版保留不變。文件在 README 說明兩者差異。

### 5.6 第一次部署出現 404

**問題**：網站顯示 `There isn't a GitHub Pages site here.`

**原因**：先 push 再啟用 Pages，第一次 Actions 在 Pages 未啟用時執行失敗。

**解決**：

```bash
gh api -X POST repos/ericyau028/fiba-3x3-schedule/pages -f build_type=workflow
gh workflow run pages.yml --repo ericyau028/fiba-3x3-schedule
```

之後每次 push 都會自動部署。

### 5.7 GitHub CLI 登入失效

**問題**：`gh auth status` 顯示 token 無效。

**解決**：

```bash
gh auth login -h github.com --web
```

使用者到 https://github.com/login/device 輸入一次性代碼。

### 5.8 Git dubious ownership

**問題**：在受控環境執行 `git push` 時出現 `dubious ownership`。

**解決**：

```bash
git config --global --add safe.directory D:/AI/Codex-Secretary/schedule-app
```

### 5.9 瀏覽器快取舊版

**問題**：部署新版後，使用者仍執行舊程式，關聯編輯還是壞的。

**解決**：

- 在 `index.html` 的資源加上版本號：`app.js?v=20260818a`
- 告知使用者強制重新整理：`Ctrl + F5`
- 日後每次改前端，記得更新資源版本號

### 5.10 測試環境被快取和舊資料污染

**問題**：同一 port 的反覆測試結果不準確。

**解決**：用全新 port 啟動靜態伺服器（例如 8768），完全隔離 localStorage 與瀏覽器快取。

```bash
python -m http.server 8768 --directory public
```
